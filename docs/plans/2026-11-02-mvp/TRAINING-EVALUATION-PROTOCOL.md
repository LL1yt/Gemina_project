# Gemina — Training and Evaluation Protocol

**Дата:** 2026-11-02. **Статус:** DRAFT / PROPOSED.  
Все настройки, лимиты и пороги ниже — предложения для рассмотрения, не экспериментально оптимальные значения. Корпус не создавался; training, generation, checkpoint, MLX/GPU, сборки и benchmarks: **NOT_RUN**. [План](DETAILED-MVP-IMPLEMENTATION-PLAN.md) · [Формулы](MATHEMATICAL-INTERFACE-CONTRACTS.md).

## 1. Один mini-batch полного BPTT

1. Взять B независимых полных примеров X:[B,T+1]. Inputs=X[:,0:T], targets=X[:,1:T+1], mask μ:[B,T]. X, inputs и targets явно привести к Int32. T обозначает число целевых позиций, а не длину исходного массива токенов.
2. Внутри одного differentiated loss closure сбросить h₀=0, p₀=(0.5,0.5,0.5) и вычислить r₀ из текущего W. У каждого batch row своё состояние. Состояние не переносится из предыдущего примера, другого lane, train или validation.
3. Последовательно выполнить T циклов R=1 с teacher forcing. Истинный следующий токен используется только как target текущего шага и вход следующего. Внутри развёртки нет sampled input, detach, optimizer updates или обращений к истории.
4. Получить единую scalar loss: sum(μ·CE)/M, M=sum μ>0. Reject пустую маску. В первом fixed-length корпусе μ=1; отдельная answer-mask используется только для отчётных метрик.
5. Один valueAndGrad по корневому Module вычисляет g_θ и g_W от одних и тех же параметров. Не вызывать отдельный backward для каждой группы и не использовать несуществующий PyTorch-style loss.backward.
6. Материализовать loss/gradients и выбранные scalars; проверить конечность. Зафиксировать pre-clipping глобальную норму и нормы групп. Один общий clipping выполняется по всему trainable tree, затем routing на W и остальные параметры.
7. MultiOptimizer с двумя Adam делает по одному update из уже вычисленных градиентов: группа с точным key field.weights и fallback θ. Обе группы имеют одинаковый update cadence; градиент не пересчитывается между ними.
8. Материализовать обновлённые model и optimizer, проверить конечность, выпустить числовое summary. Удалить references на graph/loss/logits/gradients; конечное training-state выбросить. Следующий независимый mini-batch начинает reset заново.

Eval — граница вычисления lazy arrays; отсечение состояния определяется stopGradient явно. Observer и checkpoint не вызываются из differentiated closure. При validation/test параметры и optimizer buffers неизменны, state сбрасывается. No gradient accumulation между независимыми batch по умолчанию.

### Clipping и раздельные скорости

$$G=\sqrt{\sum_{\text{trainable leaves}}\|g_i\|_2^2},\qquad
g_i'\ =\alpha g_i.$$

Предлагается официальный clipGradNorm; в проверенном исходнике α=1 при G<c, иначе c/(G+10⁻⁶). Это небольшая численная конкретизация идеального min(1,c/G), не отдельный clipping каждой группы. Далее обе группы получают свои LR.

Frozen W означает отсутствие его update и optimizer-state update. Нулевой g_W при продолжающем работать Adam не гарантирует freeze из-за momentum. При freeze W остаётся differentiable sampler по координатам. Политики freeze-after-training или unfreeze с переносом моментов не требуются первому протоколу.

## 2. Стартовая конфигурация

| Настройка | PROPOSED default | Основание / ограниченная альтернатива |
|---|---|---|
| N / C / R | 16 / 32 / 1 | Сохраняемое ядро; C — исходная гипотеза |
| H / embedding / V | 128 / 32 / 32 | Малый исходный кандидат и точный словарь ниже; H=64 только отдельный опыт, не скрытая замена контроля |
| dtype | FP32 | Прозрачный первый reference; FP16/BF16 отложены |
| B / T | 32 / 64 target positions | Короткая независимая развёртка; B=8/16 при установленной ресурсной необходимости с новым общим паспортом для сравниваемых моделей |
| Optimizer | Adam, β=(0.9,0.999), ε=10⁻⁸, biasCorrection=true | Явная воспроизводимая точка старта; MLX default correction=false |
| LR θ / W | 10⁻³ / 10⁻⁴ | Сохраняет slow-W гипотезу, не доказывает её |
| Global clipping | c=1 | Исходный кандидат; 0.5–2 только если лог норм обосновал отдельный диагностический тест |
| Weight decay / dropout / regularizers | 0 / 0 / 0 | Не добавлять средства против ненаблюдавшихся проблем |
| Scheduler | constant | Высокий LR, warmup/decay и forget/relearn отложены |
| Initialization seeds | 11,22,33 | Предлагаемые три первичные реплики; не обещание статистической значимости |

Точная инициализация:

- W: независимое Normal(0,0.1²). Не константа: иначе локальный coordinate gradient равен нулю.
- E: Normal(0,0.1²).
- GRU Wx/Wh: Uniform(−1/√H,+1/√H), как масштаб upstream; **b и bhn явно обнулить**, это изменение исходного default, где biases тоже случайные.
- M_h и M_r: независимые элементы Uniform(−s_p,+s_p), s_p=√(6/(H+C+3)); b_p=(0.5,0.5,0.5). Это общая fan-in шкала affine головы. Небольшое начальное покрытие допускается; скорость перемещения не ограничена.
- U, V_m, D: Xavier uniform отдельно по fan_in/fan_out каждой матрицы; b_y=b_o=0. U/V/W не инициализируются совместно нулём.
- Порядок и streams инициализации фиксируются по компонентам. После создания сохранить инициализированный model checkpoint для сопоставимых controls — только при будущем разрешённом исполнении.

Инициализация модели, порядок данных и генерация имеют независимые RNG streams. Предлагаются data seeds: train 1001, validation 1002, IID test 1003, composition test 1004; shuffle seed 2001. В будущем генератор использует явные MLX random keys, последовательный split текущего ключа на next/sample и целочисленное равномерное чтение query 0…7. Сохранить версию генератора, mapping, точный порядок split/RNG calls и content hashes. Диагностика не потребляет training RNG. Seeds сами по себе не гарантируют побитового равенства между версиями MLX или GPU.

**Ограниченная настройка по validation:** максимум три заранее перечисленные пары LR: (10⁻³,10⁻⁴), (10⁻³,10⁻³), (3·10⁻⁴,3·10⁻⁴). Это не декартово произведение большого поиска. Сначала менять только W-LR, если его участие слабо. σ_W=0.03 вместо 0.1 или множитель head-scale=4 вместо 1 — только следующий одиночный диагностический вариант при подтверждённой проблеме масштаба и отдельно выделенном cap. Не выбирать настройки по test.

## 3. Одна маленькая задача для первого ядра

Это упражнение на next-token computation, не соревнование по языку и не обязательная программа исследований синтетики. Главная задача M4 — проверить обучаемость всей композиции; простота задачи может сделать сравнение архитектур неинформативным.

### Словарь и грамматика

| ID | Токен |
|---|---|
| 0,1,2 | BOS, EOS, PAD |
| 3,4,5 | START, QUERY, ANSWER |
| 6,7 | NO_CUE, DIST; резерв для последующих controls |
| 8…11 | A_0…A_3 |
| 12…15 | B_0…B_3 |
| 16…23 | X_0…X_7 |
| 24…31 | Y_0…Y_7 |

Выбрать i∈{0,1,2,3}, a=2i+1, b∈{0,1,2,3}. Для пятнадцати независимо выбранных q_j∈{0,…,7} правильный ответ f(q_j)=(a q_j+b) mod 8.

Полный пример: **BOS A_i B_b START**, затем пятнадцать блоков **QUERY X_q ANSWER Y_f(q)**, затем **EOS**. Это 4+15·4+1=65 токенов, ровно T=64 следующих целей. Header/query stochastic targets включаются в общий CE наравне с остальными. Координаты, маршруты и назначения узлов генератор не сообщает.

Отдельно измерять общий NLL, NLL/accuracy пятнадцати answer positions и первого ответа. Равномерный ответ по восьми Y имеет accuracy 1/8; это простая контрольная точка. **Общий NLL не обязан стремиться к нулю:** случайный q и случайные части header нельзя угадать по префиксу. После первого ответа teacher forcing частично раскрывает правило; поэтому эта задача не используется как доказательство сохранения раннего cue через большую задержку.

### Независимые splits

Train-rule pairs: (i+b) mod 4 ≠ 0, двенадцать сочетаний. Четыре оставшихся сочетания зарезервированы для composition test; все отдельные A_i и B_b присутствуют в train.

IID validation/test используют те же двенадцать правил, но независимые example IDs/RNG namespaces и query vectors. Разделение выполняется по полным примерам, никогда по окнам одного потока. Canonical key=(i,b,q_1,…,q_15); одинаковый key не может встретиться в разных splits. Проверить совпадения до training, при коллизии повторить sample согласно фиксированной rejection-policy; не смотреть на target values при назначении split. Пересечения отдельных q или правил в IID-наборах намеренны.

До shuffle порядок генерации — lexicographic (i,b), затем последовательный index внутри пары; query vectors берутся из stream соответствующего split.

Предлагаемый небольшой объём: 1536 train (128 на rule pair), 192 validation (16 на pair), 384 IID test (32 на pair), 128 composition test (32 на удержанную pair). Все числа — **PROPOSED**, не созданные данные. Composition slice можно прочитать только после заморозки choices; отсутствие переноса не блокирует инженерный PASS ядра.

### Порядок и бюджет

Сначала tiny sanity из первых 32 train-примеров фиксированной shuffle permutation, не более 256 updates; предлагаемый диагностический ориентир — ≥95% train answer accuracy. Он не доказан заранее и не является критерием пространственного преимущества.

Tiny sanity — отдельный диагностический запуск. Перед каждым отчётным run и каждым LR trial восстановить зарегистрированную initial checkpoint соответствующей модели и создать свежие Adam-state; не продолжать из sanity или другого trial. Диагностическую экспозицию учитывать отдельно.

Далее default run: не более 1000 updates, validation каждые 50, test после фиксации конфигурации. При B=32,T=64 это 2048000 scored target positions на полный run, арифметический cap. Бюджет не открыт этой документацией. Сначала один seed; три seed и controls выполняются на M6 после технической исправности. Каждое увеличение cap или дополнительный вариант учитывается явно, без незаметного продолжения.

Mini-batches идут из детерминированной shuffle permutation train; при завершении эпохи создать следующую с сохранённым RNG. Выбирать checkpoint с минимальным validation answer NLL; при равенстве — более ранний. Также сообщать результат фиксированного последнего update, чтобы не скрывать различия фактической экспозиции best-checkpoint. Сохранить количество целей и номер update обоих. Early stop только на safety/technical failure или cap; автоматическое расширение бюджета не допускается.

## 4. Обязательные контроли M6

Каждая модель обучается **с начала** по одному split, input order, teacher forcing, числу целевых позиций, cadence updates, optimizer family, clipping и заранее ограниченному tuning allowance. Paired seeds используют одинаковые совместимые initial tensors; у другой ширины одинаковые численные матрицы не обещаются.

| Условие | Точная разница | Что проверяет |
|---|---|---|
| Gemina reference | Полный обучаемый цикл | Исходный кандидат |
| GRU-only H=128 | Input=embedding; убрать W, head, оба пути r; y=tanh(h+b_y), прежний decoder | Трудность задачи и возможность обхода W |
| Frozen random W | То же начальное W фиксировано с начала; θ обучается; gradient по адресу сохраняется | Пользу обучения значений W |
| Static addressing | p_t=p₀; head отсутствует, W/GRU/decoder обучаются; одно чтение/token | Достаточность постоянного локального вектора |
| Fixed addressing | p_t=wrap₁₆(p₀+t·(1,3,5)); head отсутствует; W/GRU/decoder обучаются | Пользу content-dependent адресов относительно заранее заданного разнообразия |
| GRU близкой ёмкости | GRU-only H=248 при том же decoder contract | Отделение от простого увеличения параметров |

Static и fixed отличаются от свободного head, поэтому не выдаются за core architecture. Fixed-path короткий и периодический; его ограниченность фиксируется, не скрывается под утверждением «оптимальный фиксированный маршрут». У обоих field-controls учёт чтений T+1 совпадает с reference.

По [аналитическому inventory](MATHEMATICAL-INTERFACE-CONTRACTS.md): Gemina 219267 параметров; GRU H128 67232; GRU H248 218552 (−0.326%). Frozen W сохраняет total capacity, но только 88195 trainable параметров; static/fixed без head — 218784 total. Отчитываться total/trainable/активно читаемые отдельно. Плотный Adam может обрабатывать весь W; sparse sampler не означает sparse optimizer. Равенство параметров не равно равенству вычислений; время/peak memory здесь NOT_RUN.

Минимальный отчёт: таблица каждого seed, total и answer NLL/accuracy на IID test, первый ответ, отдельно composition slice; paired ΔNLL, mean и разброс; число целей/updates, actual parameter count, настройки. Три seed — exploratory evidence, без автоматического заявления значимости.

Дополнительное вмешательство на замороженном trained checkpoint: нулевое чтение или фиксированная перестановка строк W с **повторным reset/replay** каждого held-out примера. Затронуть и modulation, и r-feedback. Измерить ΔNLL на тех же примерах. Это проверяет зависимость, но сдвигает распределение; не заменяет обучение controls.

## 5. Диагностика и правила выводов

| Наблюдение | Вопрос и интерпретация |
|---|---|
| Train/validation total и answer NLL; first-answer accuracy | Обучается ли доступная закономерность; расходятся ли train/held-out |
| Grad norms W, head, GRU/embedding, decoder/modulation; global norm, clipping fraction | Есть ли пути, исчезает ли адресный сигнал, не доминирует ли одна группа |
| Relative update ‖ΔW‖/(‖W‖+ε) и θ; изменение r в фиксированных probe coordinates | Реально ли меняется поле; меньший LR не гарантирует меньший функциональный сдвиг |
| Взвешенная масса чтений узлов, эффективное число посещённых узлов | Используется ли несколько областей; малая поддержка сама по себе не FAIL |
| ‖m‖/(‖h‖+ε), различия logits при вмешательстве | Влияет ли чтение на вычисление, а не только на красивую траекторию |
| max(abs(u)), fractions, torus-distance адресов | Потеря FP32-разрешения или коллапс; 16→0 не считать большим скачком |
| NaN/Inf, lifecycle/cursor/reset flags | Техническая остановка до интерпретации качества |

Read mass считать как Σ λ по фактически прочитанным узлам; reset-чтение отмечать отдельно. Ненулевой градиент сегодняшнего batch, прошлый momentum и фактические изменения W — разные множества. Fixed probe coordinates одинаковы до/после update; без них изменение r может быть следствием только нового адреса. Observer получает скопированные scalars/небольшие arrays после eval, не feed-back в Lion.

Разделять выводы:

1. **TECHNICAL_PASS:** значения/градиенты/причинность/state lifecycle исправны; есть воспроизводимое обучение доступных ответов.
2. **W_DEPENDENCE:** вмешательство влияет на held-out прогноз и W реально участвует; это ещё не польза его обучения.
3. **LEARNED_W_BENEFIT:** обучаемое W лучше frozen random W в воспроизводимом контроле.
4. **ADDRESS_BENEFIT:** learned addressing лучше static/fixed при согласованном протоколе.
5. **CAPACITY_COMPARISON:** сравнение с близкой ёмкостью ограничивает объяснение «просто больше параметров», но не доказывает уникальную пользу 3D-геометрии.

Универсального порога ΔNLL для пунктов 2–5 до данных нет. Если различия малы, меняют знак между seeds или все модели достигают потолка задачи — **INCONCLUSIVE**, не победа. Если технически исправное ядро игнорирует W, гипотеза совместного полезного вычисления в этом опыте пока не подтверждена. Не лечить это автоматически дополнительными агентами или forced coverage.

Остановить run при NaN/Inf, утечке, неверном sampler/gradient, несовместимом snapshot или исчерпанном cap. При отсутствии обучения проверять сдвиг targets, маску, r₀, paths, initialization, optimizer routing и LR; после ограниченных проверок зафиксировать отрицательный результат. Низкий train loss и гладкая animation сами по себе не основания переходить к сложным расширениям.

## 6. Последующие опыты — краткие контракты, не блокеры MVP

### TBPTT

После M1–M6 и отдельного поручения: T=128, full BPTT reference; K=8/16/32/64 и sanity K=128. Для отдельного T=128 опыта та же грамматика содержит 31 query-блок: 4+31·4+1=129 токенов; это новая версия корпуса/namespace с тем же правилом split. Для всех условий одинаковые X/μ, начальные веса, seed/order, B×T целей и **один optimizer update после всех T**.

В chunk j loss = сумма CE его позиций / общий M всего фрагмента, не отдельная необвешенная chunk mean. Получить его gradients при неизменных θ/W; сохранить численные h/p/r, отсоединить все переносимые ветви. **Не перечитывать r на границе:** W ещё не изменялось, а новое чтение откроет другую ветвь к W. Начальное r₀ находится внутри первого chunk closure.

Материализовать gradients и detached state, накопить gradient tree с явным eval, отпустить graph/logits предыдущего chunk. После всех chunks — один общий clipping и update обеих групп. K=T должен совпадать с full reference по loss/gradients/update в допуске. При K<T forward сохраняется, temporal gradient намеренно меняется.

Ожидаемая экономия относится к сохранённым активациям O(K) вместо O(T); аккумулятор gradients O(P), W и Adam buffers остаются. Простое detach при удержанных старых arrays экономию не доказывает. TBPTT смещает градиент полного objective; информация может оставаться в численном состоянии, но поздний loss не обучает напрямую путь через ранний cue за границей окна. Меньший K может снизить память и ухудшить длительные зависимости; реальные время/память/качество — NOT_RUN.

### Задержки D=8/32/96

Один отдельный paired diagnostic, T=128 target positions, 129 токенов. Все его arms начинают с одинакового нового initialization и свежих Adam-state на отдельной версии генератора, без дообучения основной задачи. Использовать основной vocabulary: BOS в index 0, cue A_0/A_1 в index 1; QUERY в index D−1, X_q в index D, ANSWER в index D+1, целевой Y_((q+c) mod8) в index D+2, EOS в index 128. Остальные позиции — независимые distractors из X_0…X_7. До scored answer нет других cue-dependent ответов. D — разность индексов потреблённых cue и ANSWER, то есть момента предсказания ответа; это не неформальное число filler.

Все позиции до EOS имеют μ=1, длина и M одинаковы между D; случайные токены после ответа не зависят от cue. Для каждого q/filler создать пару c=0/1 с одинаковым префиксом кроме cue и одинаковым суффиксом до ответа. Pair group целиком принадлежит одному independent split; query/cue balanced. NO_CUE заменяет оба cue одним токеном: для этого binary paired контроля оптимальная expected answer accuracy — 1/2, не 1/V. Отдельный no-information control независимо пересэмплирует cue для каждого примера при неизменных targets; статистическая связь с правильным ответом исчезает в ожидании, остаточные корреляции нужно проверить. Детерминированный swap A_0↔A_1 не подходит: он сохраняет обратное выучиваемое правило. Перестановка независимых distractors не должна давать ответ.

Сетка D и TBPTT используют одни и те же examples внутри каждого сравнения; chunk alignment фиксирован от index 0 и явно сообщается. Для проверки новых комбинаций правил — отдельная короткая версия двухмаркерной задачи из §3 с удержанными четырьмя rule pairs, **только первым зависимым ответом после задержки**, без промежуточных target-подсказок. Задержка и compositional transfer — разные slices, не доказательства друг друга.

### Внутренние шаги и память

R=1 остаётся ядром. R=2/4 — следующий самостоятельный опыт после определения его transition/loss: сравнить пользу дополнительных чтений и вычислений при контролируемом бюджете внешних целей и общего числа переходов. Полноценное внутреннее рассуждение и adaptive R здесь не проектируются.

W — долговременные параметры; h/p/r — активное состояние; история событий — будущий отдельный storage/retrieval механизм. Краткий snapshot/replay нужен для проверки корректности ядра, но event history с доступом Lion, fast weights, online/sleep learning и rewind не вводятся.
