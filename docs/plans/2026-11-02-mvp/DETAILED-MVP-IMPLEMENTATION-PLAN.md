# Gemina — Detailed MVP Implementation Plan

**Дата:** 2026-11-02. **Статус:** DRAFT / PROPOSED IMPLEMENTATION PLAN.  
**Область этой работы:** только документация. **Реализация и все runtime-проверки: NOT_RUN.**

План предлагает один технически определённый способ проверить исходную гипотезу: компактный Lion выбирает абсолютный адрес в обучаемом W, читает его с интерполяцией и использует чтение при следующетокенном предсказании. Сначала нужен исправный, обучаемый и воспроизводимый цикл R=1. TBPTT, искусственные задержки, читаемая история и дополнительные внутренние переходы не являются условиями первого запуска.

Публикация этого плана не утверждает его формулы и численные настройки и не разрешает исполнение. Следующее отдельное поручение на реализацию может принять предложенный паспорт целиком либо с явно перечисленными изменениями; повторное согласование каждого обратимого инженерного шага после такого поручения не требуется.

## 2. Сохраняемое ядро и предложенный паспорт

| Положение | Статус |
|---|---|
| Один Lion GRU; тор 16×16×16; совместный градиент Lion и W; next-token prediction | Задано миссией и текущим поручением |
| 32 обучаемых параметра на узел | Сохраняемая начальная гипотеза первого MVP; не найденный оптимум |
| Свободная непрерывная абсолютная координата после каждого токена | Выбор пользователя, подтверждён текущим поручением и PR #2 |
| Одно новое чтение на токен, R=1; inference с фиксированными параметрами | Граница первого MVP |
| Полный BPTT короткой независимой последовательности | Обязательный исходный референс текущего поручения |
| H=128, embedding=32, словарь 32, FP32, B=32, T=64 | Предлагаемая стартовая конфигурация |
| Absolute affine head с периодическим sampler; input GRU=[embedding; r_prev] | Предлагаемый конкретный вариант |
| Факторизованная модуляция U diag(r) V с residual h | Сохранённое предложение исходного Draft |
| Adam, две LR, clipping; точные initialization / seed / caps | Предложения протокола, не результаты настройки |

Первый артефакт будущей реализации — библиотека ядра, маленький последовательный runner и проверяемое наблюдение одного шага. Не нужны реестр агентов, абстрактная шина событий, система retrieval, плагины sampler, distributed trainer, собственное Metal-ядро или отдельный движок 3D.

Для будущего кода предлагается SwiftPM-модуль ядра и небольшой executable/тестовый target, используемые через совместимый Xcode для Metal. Это не обещание, что голый `swift build` обеспечит Metal-сборку. Если позднее понадобится `.xcodeproj`, действует [общая политика JSON-конфигурации](https://github.com/LL1yt/Project_Index/blob/main/WORKING-PREFERENCES.md). В этой работе контейнеры и manifest не создаются.

## 3. Минимальные ответственности

| Компонент | Ответственность и предел |
|---|---|
| SpatialField / Sampler | Один обучаемый массив W; stateless периодическое чтение; integer indices и float weights разделены |
| LionGRUAgent | Embedding, GRU, AddressHead; получает токен и отдельный AgentState |
| AddressHead | Три абсолютные raw-координаты из h и предыдущего чтения; без прибавления p_prev |
| Decoder | Факторизованная модуляция и logits; не изменяет h, W или историю |
| SequenceRunner | Сброс, teacher forcing / prompt / greedy generation; последовательный вызов единственного step |
| Trainer | Один loss/gradient, общий clipping, маршрутизация двух LR, границы eval и checkpoint |
| Checkpoint / Replay | Разные форматы model/training checkpoint и session snapshot; проверка идентичности |
| Diagnostics / Observer | Копии материализованных результатов; нет обратного входа в Lion |

Один корневой GeminaModel владеет всеми обучаемыми параметрами. Runtime-state, RNG данных и результаты наблюдения находятся вне дерева параметров. Один последовательный владелец модели исключает одновременную мутацию параметров UI и trainer. Эти ответственности могут соответствовать нескольким простым типам; отдельные протоколы и универсальная инфраструктура для каждой строки не нужны.

## 4. Этапы будущей реализации

Все этапы ниже **NOT_RUN**. Условия PASS описывают будущий результат, а не оценку уже существующего прототипа. Численные допуски и бюджеты имеют статус **PROPOSED**, подробно перечислены в матрице.

### M0 — закрепление условий

**Вход:** отдельное поручение на реализацию, этот пакет и актуальные AGENTS/START-HERE; повторная проверка main/PR SHA.

**Результат:** краткий паспорт конфигурации с принятыми вариантами, версиями, seeds, split и разрешёнными caps. После разрешения — проверка установленного toolchain и разрешение точных зависимостей. Кандидат MLX Swift 0.33.0 закреплён по SHA в Contracts; реальная сборка пока NOT_RUN.

**PASS:** все обязательные поля паспорта заполнены, границы ядра сохранены, установленный toolchain совместим с выбранным manifest. **FAIL/BLOCKED:** несовместимый toolchain, неразрешённая зависимость или неясный статус изменения. Не менять версию/формулу молча. Это не повод запускать альтернативные архитектуры.

### M1 — периодический sampler

**Вход:** M0, контракт размещения W и порядка восьми углов.

**Минимальный результат:** одно пакетное чтение raw-координат, canonical p, индексы углов, λ и r; маленький детерминированный эталон для значений. Начать с небольших диагностических массивов, затем точная форма 16³×32.

**Инварианты:** корректные отрицательные адреса; период 16 по каждой оси; λ неотрицательны и суммируются в 1; константное поле читается как константа; все индексы в диапазоне. Каждый batch row независим.

**PASS:** S01–S05 матрицы. **FAIL:** signed remainder, перепутанные оси/flatten, потеря batch axis или ошибка wrap. До исправления не переходить к обучению.

### M2 — аналитические, autodiff и численные градиенты

**Вход:** M1 и scalar probe с непостоянным локальным полем.

**Минимальный результат:** сопоставление формулы, autodiff и finite differences для координат и выбранных элементов W; отдельная проверка повторных индексов.

**Инварианты:** индексная ветвь отсоединена, float weights остаются в графе; вклады в повторно прочитанные узлы суммируются. На точных гранях проверяются непрерывность и одностороннее поведение, а не несуществующая единая гладкая производная.

**PASS:** G01–G04. **FAIL:** градиент индексов, detach всего r, неверный коэффициент нормировки или слишком малый ε. Зафиксировать координату/fixture и причину; не маскировать ошибку большим допуском или custom gradient.

### M3 — один полный цикл Lion + W

**Вход:** M2, точный GRU и parameter manifest.

**Минимальный результат:** reset и один step, затем короткая развёртка; logits/state и материализованный снимок для наблюдения. Никаких внутренних повторов R>1.

**Инварианты:** h — выход GRU; y не подменяет h; r₀ вычисляется внутри differentiated closure; целевой токен не доступен step. Градиент достигает W, head, GRU, embedding, модуляции и decoder в специально невырожденной fixture.

**PASS:** C01–C05, O01. **FAIL:** не зарегистрирован W, потерян r₀-path, hidden time axis перепутан, получен случайный per-token TBPTT. Не интерпретировать loss до исправления.

### M4 — первое малое совместное обучение

**Вход:** M3, split/normalization/initialization протокола, утверждённый бюджет.

**Минимальный результат:** сначала tiny memorization sanity, затем один короткий train/validation опыт на одной определённой грамматике. Нужны конечные числа, корректные updates и различимые кривые общей и answer-position ошибки.

**Инварианты:** один update на B×T целей; все состояния сбрасываются между независимыми примерами; W и Lion обучаются из одного pre-update loss; test не используется для выбора.

**PASS:** T01–T05 и диагностическая обучаемость в пределах согласованных caps. **FAIL:** NaN/Inf, утечка, нарушенный update cadence. Если всё технически исправно, но задача не выучена, статус **LEARNING_NOT_ESTABLISHED**; сначала ограниченная проверка scales/LR/masking, затем отчёт. Не считать это доказательством невозможности архитектуры.

### M5 — генерация, snapshot и replay

**Вход:** M4 с пригодной версией модели, контракты сериализации.

**Минимальный результат:** prompt → greedy continuation; save/restore на явно выбранной токенной границе; replay того же префикса и сравнение продолжения. Training checkpoint сохраняется только после завершённого update, без графа последовательности.

**Инварианты:** fingerprint параметров до/после inference одинаков; токен не потребляется дважды; snapshot другой модели отклоняется; replay использует тот же vocabulary/reset.

**PASS:** R01–R05. **FAIL:** устаревшее r, неверный cursor, отсутствующие optimizer buffers, подмена несовместимого h пересчётом r. Исправление ограничено lifecycle; читаемый журнал событий не нужен.

### M6 — роль W и адресации

**Вход:** технически исправные M1–M5, зафиксированные данные и bounded evaluation protocol.

**Минимальный результат:** таблица независимых запусков Gemina, GRU-only, frozen random W, static/fixed-address и GRU близкой общей ёмкости. Начать с дешёвого smoke каждого контроля, затем согласованные seeds и равное число целей/updates.

**Инварианты:** frozen W сохраняет coordinate gradients; GRU-only убирает оба пути r; проверки trained checkpoint не заменяют controls from scratch; capacity и compute не отождествляются.

**PASS:** протокол E01–E04 выполнен, выводы соответствуют уровню свидетельств. **Отрицательный/INCONCLUSIVE результат допустим:** нет надёжной пользы W/head, задача слишком проста или эффект меньше разброса. Это не повод автоматически добавлять память, агентов или штраф покрытия.

### M7 — отдельные последующие исследования

**Вход:** результаты ядра и отдельное поручение на конкретный опыт.

**Возможный результат:** TBPTT при T=128, K=8/16/32/64 и sanity K=128; задержки D=8/32/96. Краткие контракты находятся в конце Training Protocol. Качество и память сравниваются при согласованном update cadence; фактические измерения NOT_RUN.

**PASS/FAIL:** сначала эквивалентность forward и K=T, затем честно измеренный эффект. Если польза не установлена, остаётся full-BPTT reference. R=2/4, retrieval, online learning и история требуют следующих отдельных планов.

## 5. Первое наблюдение и полезные метрики

На M3 достаточно режима «один токен»: вход, top prediction, координата, r и восемь λ. На M4 добавить кривые train/validation NLL и answer accuracy. На M6 — разности качества контролей на одних примерах. Это позволяет увидеть механизм без обязательной разработки большого UI.

Observer показывает понятный текущий результат; Diagnostics — gradient norms, реальные updates W, концентрацию чтений и масштаб модуляции. Для каждой метрики нужен короткий текст: что означает, как понимать рост/падение, какой сбой она помогает обнаружить. Линия траектории через 16→0 отображается с учётом тора. Цвет не получает выдуманного семантического значения.

Наблюдение не сохраняет граф и не предоставляет агенту доступ к логам. Конкретная SwiftUI-оболочка может быть следующим небольшим шагом после работающего runner.

## 6. Что считается завершением этого плана

Пакет достаточно определяет минимальное ядро, чтобы после его рассмотрения coding-agent мог реализовать M1–M6 без выбора другой GRU-формулы, неявной loss-normalization, скрытой схемы detach или догадок о snapshot boundary. Открытые решения имеют предлагаемые defaults и явные альтернативы.

Сейчас завершена только документационная подготовка. Ни один runtime PASS не заявлен; не создавались исходники прототипа, корпуса или checkpoints, не выполнялись установки, сборки, обучение, генерация и benchmarks. Состояние веток и точные источники записаны в [PR Alignment](PR-ALIGNMENT.md).
