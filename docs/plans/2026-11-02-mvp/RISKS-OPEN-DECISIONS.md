# Gemina — Risks and Open Decisions

**Дата:** 2026-11-02. **Статус:** DRAFT / PROPOSED.  
Риски ниже не считаются наблюдёнными сбоями. Все runtime-проверки и эффекты: **NOT_RUN**. [План](DETAILED-MVP-IMPLEMENTATION-PLAN.md) · [Матрица проверок](TEST-MATRIX-ACCEPTANCE.md).

## 1. Риски первого ядра

| Риск | Что позволит его различить | Первое действие при обнаружении | Что не добавлять заранее |
|---|---|---|---|
| Lion игнорирует W | Малые изменения предсказаний при вмешательстве, frozen/static controls не хуже; gradients сами по себе недостаточны | Проверить оба пути r, learning scale и простоту задачи; сравнить равные LR в объявленном cap | Decoder только через W, penalty «обязательно использовать поле» |
| Адреса сосредоточены в малой области | Weighted read mass, raw-scale, вариативность r и качество controls | Различить полезную специализацию и отсутствие эффекта; проверить head init/градиент | Uniform coverage, noise exploration, новые агенты |
| Слабый gradient head | Norm по head и u в невырожденной fixture, finite differences | Проверить detach indices vs целого r, непостоянное W, модуляцию, initialization | REINFORCE, custom VJP и global lookup |
| Шов или насыщение координат | Off-boundary derivatives, one-sided seams; max(abs(u)) и FP32-разрешение | Проверить positive periodic indices и scale; альтернативную head менять отдельным контролем | Clamp координаты, трактовка излома как гладкой точки |
| Неудачное отношение LR | Реальный relative update W/θ, change r на фиксированных probes, seed effects | Slow/equal LR по ограниченному протоколу | Большой tuning sweep, предположение «slow значит stable» |
| W лишь добавляет ёмкость | Сначала M6-A: GRU-only H=128, затем M6-B: GRU-only H=248 близкой total capacity | Отчитаться по обоим controls, frozen/static ablations и compute-различию | Заявление пользы геометрии по сравнению только с маленькой GRU |
| Утечка targets или состояния | Prefix causality, batch isolation, duplicate keys, split/RNG manifest | Остановить run, исправить split/reset/shift; затронутый test перестаёт быть чистым | Объяснение внезапного качества «эмерджентностью» |
| Snapshot относится к другим весам | Full model/config/vocabulary fingerprints, cursor | Reject + reset или полный нужный replay; один пересчёт r не исправляет h | Тихая миграция старого h |
| Случайное усечение BPTT | r₀-path, двухшаговая derivative fixture, single loss closure | Убрать per-token valueAndGrad или лишний detach; проверить aux semantics | Компенсация более длинным training |
| Удержание lazy graph | Lifetime review и разрешённое позже измерение памяти | Материализовать summaries, убрать ссылки Observer/списки старых losses | TBPTT до выяснения причины |
| Numerical divergence | Finite checks до/после update, norms/clipping | Остановить, сохранить metadata; проверить масштаб и LR | Silent NaN repair, автоматический рост бюджета |
| Версии API/зависимостей не совпали | Exact pin, actual toolchain, parameter inventory | Заблокировать setup, описать конкретное несовпадение | Floating main или downgrade без записи причины |

Плотный Adam с momentum может менять ранее посещённый узел при нулевом текущем gradient. Это не утечка или «дальнее распространение смысла» само по себе. Отдельно измеряются read support, gradient support и update support.

## 2. Решения для рассмотрения до реализации

Сохраняемое ядро уже задано текущим поручением. Следующие строки — **предлагаемые defaults**, по которым инженер сможет работать, если они приняты вместе с поручением на реализацию. Ни одна строка не стала принятой только из-за этого Draft PR.

| ID | Предлагаемый выбор | Альтернатива и причина вернуться к вопросу |
|---|---|---|
| P01 | Absolute affine→periodic sampler; no p_prev feedback | Sigmoid/tanh или angle-pair после данных о масштабе/градиентах |
| P02 | Factorized modulation U(r⊙V_m h) плюс residual h | Простая проекция r в h, если modulation объективно мешает обучению; отдельное сравнение |
| P03 | H128, d32, C32, FP32; GRU reset-after | H64 как дальнейшая проверка компактности; другие GRU equations не подменяют baseline |
| P04 | p₀=(0.5,0.5,0.5), r₀ внутри графа, одна новая выборка/token | Иное reset только с новой policy/hash; не random start по умолчанию |
| P05 | B32,T64, полный BPTT, Adam two LR 10⁻³/10⁻⁴ | Ограниченная LR-сетка и B8/16 при установленной необходимости; budgets пересчитать |
| P06 | Одна 32-token rule grammar, independent IID splits, held-out rule pairs | Малый текстовый корпус или иная задача после корректного ядра; нет автоматического переноса Logos Seed |
| P07 | Предложенные допуски и caps из Test Matrix / Protocol | Уточнять по диагностике и заранее фиксировать, не менять после просмотра test ради PASS |
| P08 | MLX Swift 0.33.0 по точному SHA, совместимый Swift ≥6.3 | Конкретный другой проверенный pin при incompatibility; текущий Mac toolchain неизвестен |
| P09 | Snapshot после consumption и до sampling, r сохраняется | Другие boundaries требуют pending-token/RNG contract; сейчас не нужны |
| P10 | Небольшой runner и Observer, затем при необходимости SwiftUI | Внешний UI/3D-world не нужен для M1–M4 |

В исходной миссии C=32 — начальная гипотеза; текущее поручение требует сохранить её для первого MVP. Она не входит в список параметров первого tuning sweep. R=1, отсутствие дополнительных агентов и inference без updates также не являются tuning choices.

## 3. Что именно может показать первый опыт

Корректный цикл с обучением и replay устанавливает техническую осуществимость выбранной композиции. Функциональная зависимость предсказаний от W показывает участие поля. Сравнение с frozen W отдельно проверяет пользу его обучения; static/fixed addressing — пользу выбора адресов; близкая по ёмкости GRU — альтернативное объяснение дополнительными параметрами.

Даже положительные результаты не доказывают уникальность 3D-тора, существование семантической карты, точную память диалога, глобальный поиск адресов, преимущество над LLM или самостоятельную кооперацию агентов. При совпадающих результатах на простой задаче разумный вывод — ограниченная информативность этого опыта. Следующая более различающая задача требует отдельного решения, а не немедленного усложнения ядра.

## 4. Отложенные направления

После результатов ядра можно отдельно выбрать TBPTT K=8/16/32/64 при T=128, controlled D=8/32/96 или R=2/4. В этом пакете для них есть только достаточный контракт сравнения; они не становятся зависимостями M1–M6.

История событий, выбранная в PR #2 как одна запись с восьмиузловыми weighted links, остаётся будущим самостоятельным storage/retrieval механизмом. Архитектурная граница state/parameters/Observer позволяет добавить её позже без превращения W в журнал. Online learning, fast weights, Eagle, несколько агентов, многослойное поле, автономный выбор R и forget/relearn остаются вне MVP.

## 5. Неизвестные эмпирические величины

Сходимость, полезность W, распределение адресов, лучший LR/scale, достаточный budget, actual peak memory, время шага, Metal repeatability, Swift-сборка и композиция APIs не измерены. **NOT_RUN** — отсутствие запуска, а не отрицательный результат. Аналитический подсчёт параметров и чтение исходников не заменяют эти измерения.
