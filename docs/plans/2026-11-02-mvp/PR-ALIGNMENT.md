## 2. Приоритет и статусы

Главное основание текущей работы — прямое поручение **«Gemina — Detailed MVP Implementation Plan»** от 2026-11-02: отдельный Draft PR, шесть документов, обновление указателей, без реализации и запусков. Оно разрешает подробное проектирование, которое в прежнем outline было отложено.

| Положение | Статус / основание | Как отражено здесь |
|---|---|---|
| Один GRU, 16³ тор, next-token, общий gradient, frozen inference | Миссия и подтверждённое текущее ядро пользователя | Обязательная граница |
| C=32 | Начальная гипотеза миссии, явно сохраняемая текущим поручением | Fixed first configuration; не результат оптимизации |
| Absolute continuous address вместо bounded-step | Пользовательский выбор, записанный PR #2 и повторённый текущим поручением | Head предсказывает абсолютный адрес |
| Одно новое чтение/token, R=1 | Подтверждение пользователя в PR #2 и текущем запросе | T новых чтений плюс reset r₀, без скрытых R>1 |
| Full BPTT на коротких последовательностях | В ранних документах предложение; сейчас явный reference пользователя | Основной protocol; TBPTT только последующий опыт |
| История: одна запись и восемь weighted links | Выбранная **будущая** схема из PR #2 | Не часть MVP, не доступна Lion |
| Локальность gradient, ограничения дальнего поиска, prior-art parallels | Аналитические выводы REVIEW DRAFT PR #3 | Учтены в рисках/контролях; не эмпирические результаты |
| K/D/R сетки и краткий итеративный акцент | Исследовательское предложение PR #4; текущее поручение требует сохранить кратко | Неблокирующие последующие опыты |
| Affine+periodic sampler, точный GRU, modulation, initialization, H/B/T, LR, tolerance/caps | Предложения этого плана или сохранённые кандидаты Draft | PROPOSED, не новые принятые ADR |
| Успешность обучения, польза W, адресации или R>1 | Не проверены | NOT_RUN |

Базовые источники: [миссия](../../../sources/GEMINA-Research-Mission-v0.2.md), [DOCX](../../../sources/Gemina_Architecture_Draft_v0_1.docx), [AGENTS](../../../AGENTS.md), [правила Project_Index на проверенном main](https://github.com/LL1yt/Project_Index/blob/cececa48047f49e7507ba404a41e480aa795b2be/WORKING-PREFERENCES.md).

## 3. Расхождения и их разрешение в предлагаемом плане

| Источник / расхождение | Уточнение этого пакета |
|---|---|
| Main / DOCX используют p_prev+0.5 tanh; миссия говорит, что свободные прыжки первоначально не требуются | Последующий выбор пользователя задаёт свободный абсолютный адрес. Источники сохранены, old formula — исторический контроль |
| PR #2 приводит sigmoid только как пример, точная голова открыта | Предложен affine raw u с periodic trilinear read. Sigmoid/tanh/angle-pair сохранены как альтернативы с рисками |
| В таблице DOCX C=32 записано без оговорки | Сохранён статус начальной гипотезы миссии |
| PR #2 register говорит «связная генерация как первый наблюдаемый результат» | Его основной текст и текущее поручение не требуют связного естественного языка. MVP проверяет закономерное продолжение и корректность inference |
| Исторический Training Design обсуждает stateful TBPTT с update W и перечитыванием r между фрагментами | Новый **сравнительный** TBPTT держит W/θ неизменными внутри T, один update после всех chunks; detached r между chunks не перечитывается. Это другой явно заданный protocol, не опровержение исторического |
| PR #4 отделяет одношаговый credit как отдельный режим | При полном отсечении всех recurrent inputs и том же cadence K=1 — предельный случай TBPTT; частичный detach из PR #3 имеет иной graph. K=1 не включён в первый опыт |
| Snapshot исходного Draft допускает восстановить r чтением | Здесь r сохраняется для точного numerical continuation; canonical p служит проверке/наблюдению. Re-read при restore не должен скрыто менять state |
| PR #3 описывает локальный sampler-gradient | Свободный адрес не означает глобальный поиск; весь W не обязан посещаться равномерно. Это ограничивает выводы, не запрещает первый опыт |
| PR #4 местами называет R «дополнительными» переходами, хотя таблица горизонтов считает шаги на token | Здесь R — общее число внутренних переходов/чтений на внешний токен: R=1 исходный цикл, R=2 означает всего два, не три |
| PR #4 предлагает широкую последовательность дополнительных исследований | Текущее поручение ограничивает внимание ядром. TBPTT/D/R>1 и история не блокируют M1–M6 |

Никакая точная формула, numerical threshold или experimental advantage не принимается путём «согласования» этих документов. Для каждого предлагаемого выбора указан default и способ проверки.

## 4. Изменения этой ветки и последующее объединение

Новый пакет расположен в `docs/plans/2026-11-02-mvp/`. Обновляются START-HERE, карта, provenance и реестр предложений; реестр решений фиксирует только явно заданные текущим поручением границы. У исторических производных спецификаций добавлены указатели на новое планирование, их формулы не переписаны.

Ветка создаётся **от проверенного main**, не от PR #2/#3/#4 и не от их синтетических merge commits. Их новые файлы не копируются с притворством, что они уже в main: ссылки идут на собственные PR heads. Слияния отсутствуют.

При будущем отдельном объединении возможны текстовые конфликты в START-HERE, DOCUMENTATION-MAP, PROVENANCE и registers. Их следует согласовать содержательно, сохранить три источника и новые статусы, убрать только дублирующие указатели. Включение нашего Draft не является автоматическим принятием всех предложений других PR.

Исходная mission и DOCX сохраняются побайтно. Прочитанный DOCX: 68751 байт, SHA-256 `525957abbd3a68ad1eeb9f83d0a8ab5a06dfc9a5b71bfebf39d58b1f10209f49`. Совпадение hash проверено; историческая NumPy-проверка из DOCX не воспроизводилась.

Организационные связи не изменились: Gemina самостоятельна, общая реализация с Logos Seed не установлена, этап остаётся исследовательским. Поэтому внешний Project_Index не требует дублирования подробного плана. Запись GitHub не означает синхронизацию папки на Mac пользователя или памяти другого агента.
