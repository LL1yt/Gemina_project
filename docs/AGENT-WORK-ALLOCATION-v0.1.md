## Поручение M1: минимальный объём

**Дано поручение начать только реализацию M1** по уже принятому M0 и контрактам PR #5. Моргана работает в своей ветке и создаёт **Draft PR без merge**. Не расширять архитектуру. Если версия среды/зависимости/права мешают исполнению — сообщить BLOCKED и детали, не менять формулы или toolchain молча.

Результат M1: минимальный периодический 3D trilinear sampler для W:[4096,32], raw u:[B,3], r:[B,32], угловые индексы и λ; корректный positive wrap на отрицательных/граничных адресах, оси, batch-формы. Тесты S01–S05 с независимыми аналитическими значениями; записать SHA кода, версию Swift/MLX/устройства, что реально RUN/PASS/FAIL/NOT_RUN. **M2, обучение и создание полной модели не разрешены этим поручением.**

Вергилий сначала готовит собственные тестовые случаи/эталоны по закреплённому математическому контракту (без просмотра реализации Морганы), затем после готовности PR проводит проверку математики и кода. Это **независимый аудит, а не второй вариант реализации или состязание**. Не менять код Морганы без отдельного разрешения; сообщить замечания ей и владельцу.

Роль Архивариуса — координатор контрактов и документации, а не участник конкурса или единственный судья. Владелец решает, что принимать в main, когда открывать M2 и в каких условиях запускать тесты на локальном Mac.

## Будущие соревнования — только при реальной пользе

Две независимые реализации использовать **избирательно** для сложных, существенно неоднозначных частей, где важно увидеть разные инженерные решения. Это не обязательное условие для каждого уровня A и не критерий PASS. Для выбранного будущего тура владелец может получить две анонимизированные версии кода и дать их двум независимым оценщикам без имён авторов и прежних оценок. Не нужны специальные секретные ветки, оркестратор или инфраструктура ради игры. Если участники видели работы друг друга, отметить ограничение независимости честно.

[Gemina Agent League](agent-evaluations/LEADERBOARD.md) — только история **фактически проведённых состязаний**. Обычные M1 code review и проверки S01–S05 не добавляют побед или баллов.

**Никаких автоматически присвоенных наград или рангов моделей.** Сначала работающий объект исследования; затем проверка его свойств; затем расширения. 😼
